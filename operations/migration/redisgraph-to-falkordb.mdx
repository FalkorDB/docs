[RedisGraph reached end-of-life](https://redis.io/blog/redisgraph-eol/) on January 31, 2025. It is no longer maintained, no new patches are released, and RedisGraph commands are disabled on Redis Enterprise Cloud.

**FalkorDB is the direct successor to RedisGraph**, built and maintained by the engineers behind the original RedisGraph project. It keeps the same sparse-matrix and [GraphBLAS](https://graphblas.org) architecture, the same `GRAPH.*` command API over the Redis protocol, and reads your existing RedisGraph RDB files as-is — so moving off a deprecated RedisGraph deployment is a restore, not a rewrite.

<Note>
  Looking for the fastest path off RedisGraph? Jump straight to the [migration steps](#migration-steps). Your `dump.rdb` loads into FalkorDB without conversion.
</Note>

## Why FalkorDB Is the RedisGraph Alternative

* **Same team, same lineage.** FalkorDB continues the RedisGraph codebase and its linear-algebra query engine, led by the people who created it.
* **Drop-in API compatibility.** `GRAPH.QUERY`, `GRAPH.RO_QUERY`, `GRAPH.EXPLAIN`, `GRAPH.PROFILE`, `GRAPH.DELETE`, and `GRAPH.LIST` behave as they did in RedisGraph. See the [command reference](/commands).
* **Zero-conversion data migration.** FalkorDB loads RedisGraph RDB snapshots directly. There is no export/import pipeline, no CSV round-trip, and no ETL job.
* **No client rewrite.** Existing RedisGraph client code keeps working; [official FalkorDB clients](/getting-started/clients) are available for Python, JavaScript, Java, Go, Rust, and C#.
* **Actively developed.** Ongoing releases add capabilities RedisGraph never shipped, including [vector indexes](/cypher/indexing/vector-index), [full-text search](/cypher/indexing/fulltext-index), [graph algorithms](/algorithms), [UDFs](/udfs), and [GraphRAG tooling](/genai-tools/graphrag-sdk).

## Migration Steps

FalkorDB is fully compatible with RedisGraph RDB (Redis Database) files, making migration straightforward.

### Step 1: Create RDB Snapshot from RedisGraph

Create a snapshot of your RedisGraph database using the `SAVE` or `BGSAVE` command:

```bash
# Connect to your RedisGraph instance
redis-cli

# Create snapshot (blocks server during save)
SAVE

# Or create snapshot in background (recommended for production)
BGSAVE
```

This creates a `dump.rdb` file in your Redis data directory.

### Step 2: Load RDB File into FalkorDB

#### Using Docker

When using the FalkorDB Docker image, mount your RDB file and configure Redis to load it:

   ```bash
   docker run -it -p 6379:6379 -v $(pwd):/data -e REDIS_ARGS="--dir /data --dbfilename dump.rdb" falkordb/falkordb
   ```

   Make sure to place the RDB file in the directory mapped to the Docker volume.
   For FalkorDB Cloud, follow the cloud provider’s instructions for uploading and restoring from an RDB file.

**Important:** Ensure your `dump.rdb` file is placed in the directory mapped to the Docker volume (`$(pwd)` in the example above).

#### Using FalkorDB Cloud

For FalkorDB Cloud deployments, follow the cloud provider's instructions for uploading and restoring from an RDB file.

## Verification

After loading the RDB file, verify your data:

```bash
# Connect to FalkorDB
redis-cli

# List all graphs
GRAPH.LIST

# Query a graph to verify data
GRAPH.QUERY your_graph_name "MATCH (n) RETURN count(n)"
```

## Best Practices

* **Verify RDB Integrity:** Check the RDB file integrity before and after transfer
* **Plan for Downtime:** Consider downtime requirements and data consistency during migration
* **Test First:** Always test the migration in a staging environment before production
* **Backup:** Keep backups of both the source RedisGraph data and the RDB file
* **Monitor:** After migration, monitor FalkorDB performance and verify queries work correctly

## After You Migrate

Once your graphs are running on FalkorDB, these are the capabilities that were never available on RedisGraph:

* [Vector indexes](/cypher/indexing/vector-index) and [full-text indexes](/cypher/indexing/fulltext-index) for hybrid semantic and graph retrieval.
* [Graph algorithms](/algorithms) such as PageRank, betweenness centrality, WCC, and max-flow.
* [User-defined functions](/udfs) for logic that used to live in application code.
* [GraphRAG SDK](/genai-tools/graphrag-sdk) and the [MCP server](/genai-tools/mcpserver/quickstart) for GenAI and agent workloads.
* [Replication](/operations/replication), [clustering](/operations/cluster), and [Kubernetes deployment](/operations/k8s-support) for production scale.

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="Is RedisGraph deprecated, and when did it reach end-of-life?">
    Yes. Redis announced the RedisGraph end-of-life in July 2023. End of support was January 31, 2025, the GitHub repository is no longer maintained, and RedisGraph commands are disabled on Redis Enterprise Cloud. See the [official EOL announcement](https://redis.io/blog/redisgraph-eol/).
  </Accordion>
  <Accordion title="What is the best RedisGraph alternative?">
    FalkorDB. It is the successor to RedisGraph, built by the engineers behind the original project on the same GraphBLAS sparse-matrix engine. It keeps the `GRAPH.*` command API and the Cypher dialect you already use, reads your existing RDB files, and is actively developed — so it is the only alternative that requires neither a data conversion nor a query rewrite.
  </Accordion>
  <Accordion title="Is FalkorDB a drop-in replacement for RedisGraph?">
    In practice, yes. FalkorDB speaks the Redis protocol, exposes the same `GRAPH.QUERY` and `GRAPH.RO_QUERY` commands, and loads RedisGraph RDB snapshots directly. Most deployments only change the connection endpoint. Review [Cypher support](/cypher/cypher-support) and [known limitations](/cypher/known-limitations) if you rely on unusual clauses.
  </Accordion>
  <Accordion title="Is FalkorDB fully compatible with RedisGraph RDB files?">
    Yes. FalkorDB is fully compatible with RedisGraph RDB files. Simply load your existing `dump.rdb` into FalkorDB and your graphs will be available immediately.
  </Accordion>
  <Accordion title="Do I need to stop RedisGraph before creating the RDB snapshot?">
    For a consistent snapshot, use `BGSAVE` which creates a background snapshot without blocking the server. For absolute consistency, use `SAVE` which blocks but ensures no writes during the snapshot.
  </Accordion>
  <Accordion title="Can I migrate from RedisGraph Cloud to FalkorDB Cloud?">
    Yes. Export an RDB file from your RedisGraph Cloud instance, then follow your FalkorDB Cloud provider instructions for uploading and restoring from the RDB file.
  </Accordion>
  <Accordion title="Will my existing RedisGraph client code work with FalkorDB?">
    Yes. FalkorDB is API-compatible with RedisGraph. Your existing client code using `GRAPH.QUERY` and `GRAPH.RO_QUERY` commands will work without modifications. For new work, prefer the [official FalkorDB clients](/getting-started/clients), which are actively maintained.
  </Accordion>
  <Accordion title="Do I have to rewrite my Cypher queries?">
    No. FalkorDB implements the same openCypher dialect RedisGraph did, plus extensions. Queries written for RedisGraph run unchanged in the vast majority of cases.
  </Accordion>
  <Accordion title="Can I keep running RedisGraph instead of migrating?">
    You can, but it is unsupported, unpatched software: no security fixes, no bug fixes, and no compatibility work for newer Redis versions. Migrating to FalkorDB restores an actively maintained path without changing your data or queries.
  </Accordion>
</AccordionGroup>
